# AI 协作自检

Ryan Agent Work Kit 不只让项目更适合 AI 接管，也帮助用户逐步形成更好的 AI 协作习惯。

这个模块借鉴 4D AI Fluency 思路，但做成轻量版：

```text
委托 Delegation
  ↓
描述 Description
  ↓
判断 Discernment
  ↓
审慎 Diligence
```

目标不是证明用户“会不会用 AI”，而是让每次复杂协作结束后，多看一眼：哪里可以少返工，哪里可以更安全，哪里可以让 AI 更容易接管。

## 四个问题

| 维度 | 小白解释 | 在本工具包里的对应物 |
| --- | --- | --- |
| 委托 | 这件事该不该交给 AI，交给谁 | S0/S1/S2/S3、主控/子 agent、任务 lane |
| 描述 | 我有没有把任务说清楚 | `docs/current-goal.md`、Task Card、提问模板 |
| 判断 | 我有没有验证 AI 的结果 | `doctor`、测试、diff、截图、日志、人工确认 |
| 审慎 | 我有没有守住安全和公开边界 | 安全规则、最小披露、Obsidian 边界、公开包扫描 |

## 什么时候用

不要每个小任务都填表。优先在这些场景使用：

- S2/S3 复杂任务。
- 多 agent 或外部 CLI 协作。
- 出现返工、低采纳、误跑、超时或验证不足。
- 用户觉得“这次慢、绕、重复消耗、不该这么拆”。
- 任务结束后发现有可复用提问方式、验证方法或安全规则。

## 怎么用

复制模板：

```bash
cp templates/ai-collaboration-reflect.zh-CN.md ./my-project/docs/handoffs/<task-name>-reflect.md
```

或者只在完成汇报里给出一句轻量自检：

```text
AI 协作自检：这次委托合适，描述缺少验收标准，判断通过测试和 diff 验证，审慎无公开风险。下次先写验收标准。
```

## 原则

- 不打分。
- 不排名。
- 不抓完整聊天记录。
- 不写密钥、完整日志、会话流水、客户资料或私有路径。
- 只沉淀能减少返工、提升验证、降低风险或节省上下文的经验。

## 和 AgentOps 的关系

AgentOps 看协作结果，例如耗时、返工、采纳率和错误类型。

AI 协作自检看协作习惯，例如任务是否委托对了、是否描述清楚、是否验证充分、是否守住边界。

两者可以一起用，但都应该保持轻量。
