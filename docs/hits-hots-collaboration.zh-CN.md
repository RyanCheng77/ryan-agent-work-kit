# HITS 与 HOTS 协作

本工具包用两种互补的协作模式。它们是本工具包的工作标签，不宣称是行业标准术语。

- **HITS（Human in the Swarm）**：人是协作团队中的活跃成员。任务进行中可以补充上下文、作出决策、调整范围、接管任务、增加或替换 agent。
- **HOTS（Human on the Swarm）**：人在协作团队外观察，并对高风险动作进行授权。

## 默认规则

普通协作默认使用 HITS。让人的判断力靠近产品方向、范围、架构和质量决策。

遇到破坏性、不可逆或会扩大影响面的动作，先切换到 HOTS 闸门。包括：

- 删除数据或分支；
- 改权限或凭证；
- 发布、合并、部署或对外提交；
- 向外部服务披露代码、日志、客户数据或其他私密材料；
- 数据迁移、合规敏感改动或明显金额支出。

闸门意味着等待指定决策人明确决定，不代表 agent 可以持续重试，也不代表可以没有证据地转移责任。

## 共享任务状态

任务卡和交接使用一组小而明确的状态：

| 状态 | 含义 | 下一步 |
| --- | --- | --- |
| `in_progress` | 在已批准范围内推进。 | 继续执行并展示证据。 |
| `waiting_for_human` | 需要指定的人作出决策。 | 暂停受影响的 lane，说明问题。 |
| `recommend_agent_switch` | 当前 agent 不匹配，或缺少所需能力。 | 给出证据和替代建议，由主控决定。 |
| `ready_for_acceptance` | 已完成到可以验收的程度。 | 查看 diff、测试、截图、日志或其他证据。 |
| `stopped` | 未完成即结束。 | 记录原因、安全交接点和下一步选择。 |

不要把普通的不确定性写成 `waiting_for_human`。必须写明具体决策、选项、负责人和影响。不要把 `recommend_agent_switch` 当作逃避责任的状态。

## 任务卡字段

对 S2/S3、委派或容易漂移的任务，只补充真正有用的字段：

- 协作模式：通常为 `HITS`；有风险时写明 HOTS 闸门；
- 当前协作状态；
- Ryan 介入点：哪些决策值得 Ryan 看一眼；
- 每个闸门的决策负责人；
- 升级条件：什么可观察信号会暂停或改派工作。

这是协作契约，不是实时编排系统。CLI 保持薄适配层；终端输出、日志、diff 和验证仍是证据。

如果项目使用 Taskboard，把它作为跨会话任务和验收事实源，而不是 HITS 状态的镜像。详细分工见 `docs/taskboard-ego-workflow.zh-CN.md`。

## 观察后改进

复杂多 agent 协作中，AgentOps 可以按需记录人类介入是否改变范围、是否发生转交/接管、是否暴露了 agent 匹配问题。记录事件类型和证据，不记录私密聊天全文。

出现重复模式后，再判断下一步应该写入任务卡、项目规则、脚本、hook、skill 还是 agent 角色。
