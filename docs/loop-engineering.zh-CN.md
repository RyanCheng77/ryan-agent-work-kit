# Loop Engineering 轻量版

Loop Engineering 在这个工具包里不是“大型自动化引擎”，而是一组小而安全的 AI 工作闭环。

目标很简单：

```text
目标清楚
  ↓
上下文克制
  ↓
执行可见
  ↓
验证明确
  ↓
经验可沉淀
```

## 小白版：内环、中环、外环

可以把 AI 协作理解成三层 loop：

| 层级 | 解决什么问题 | Ryan Agent Work Kit 怎么做 |
| --- | --- | --- |
| 内环 | 当前这个任务怎么更快做对 | 读规则、控上下文、小步改、跑验证、防重复失败 |
| 中环 | 复杂任务怎么少返工、会协作 | S0/S1/S2/S3 路由、任务卡、多 agent 边界、AgentOps 观察 |
| 外环 | 项目和个人经验怎么越用越顺 | `AGENTS.md`、`docs/`、Obsidian、skill/agent-roles、hook/脚本沉淀 |

最重要的判断是：

- **内环追求快**：一个任务内快速读、改、测、修。
- **中环追求稳**：任务变复杂时，先拆边界、再并行、再验收。
- **外环追求复用**：只有反复出现、能降低返工或风险的经验，才沉淀成模板、脚本、hook、skill 或角色 agent。

不要把外环流程塞进每个小任务。S0/S1 小事留在内环，S2/S3 复杂事才进入中环和外环。

## 行业信号

最近 AI coding 工具的发展有几个共同方向：

- 更重视项目级规则和 repo instructions，让 agent 进入仓库后先读固定上下文。
- 更重视长任务、后台任务、终端可见进度和可恢复交接。
- 更重视人的协作习惯反思，不只是提升模型能力，也提升用户给任务、验收和边界判断的能力。
- 更重视安全、权限、最小上下文和可审计记录。

Ryan Agent Work Kit 对这些趋势的吸收方式很克制：不追求一次性自动化所有事情，而是先把“能被 AI 稳定接管的项目标准”做好，再按需推荐 skill、agent、hook 或自动化。

## 为什么需要 loop

只让 AI 更快生成内容，不一定会减少返工。真正影响交付质量的，通常是：

- AI 有没有读到正确项目规则。
- 任务范围是否清楚。
- 执行过程是否能被观察。
- 结果是否有测试、截图、diff、日志或人工确认。
- 踩坑经验是否能被下一次复用。

所以 Ryan Agent Work Kit 不追求“无人值守一直跑”，而是先把常见 AI 协作做成可停止、可验证、可复盘的小 loop。

## 三个默认小闭环

### 1. Project Context Loop：项目上下文内环

```text
用户提出任务
  ↓
Agent 读取 AGENTS.md
  ↓
Agent 读取 docs/current-goal.md
  ↓
Agent 检查分支、工作区和风险
  ↓
Agent 决定直接做、先想清或分头查
```

这个 loop 解决“AI 每次都从零理解项目”的问题，属于任务内环的入口。

### 2. Observable Execution Loop：可观察执行中环

```text
任务卡或口头范围
  ↓
本地执行或外部 CLI 子 agent
  ↓
Codex 右侧 workspace 终端可见
  ↓
.agent-runs/ 保存日志
  ↓
主控用终端、日志、产物和 diff 判断进展
```

这个 loop 解决“外部 CLI 跑到哪了、是不是卡住了”的问题，属于复杂任务的中环。

### 3. Verify And Learn Loop：验证沉淀外环

```text
完成改动
  ↓
运行验证或说明无法验证
  ↓
汇报风险和下一步
  ↓
必要时记录 AgentOps
  ↓
必要时同步 Obsidian 或沉淀 skill
```

这个 loop 解决“做完不知道是否可靠、经验没有留下来”的问题，属于项目和个人系统的外环。

## 放在哪一层

| 场景 | 默认层级 | 推荐动作 |
| --- | --- | --- |
| 改一个小 bug、补一段文案、跑一个检查 | 内环 | 直接做，简短验证 |
| 新功能、多文件修改、UI/行为变化 | 中环 | 先对齐方案，再实现和验证 |
| 两个以上独立调查方向或多失败点排查 | 中环 | 拆 2-4 条并行线，主控保留关键路径 |
| 多 agent/外部 CLI 协作变慢、返工或低采纳 | 中环 + 外环 | 记录 AgentOps，下一次调整调度方式 |
| 同类流程重复 3 次以上 | 外环 | 判断是否脚本化、模板化、hook 化或 skill 化 |
| 产生跨项目经验 | 外环 | 同步 Obsidian，必要时更新个人偏好或 skill |

## 反模式

这些不是 Ryan Agent Work Kit 想鼓励的 loop：

- 没有停止条件，让 agent 一直自动尝试。
- 没有验证，只相信 agent 自评。
- 没有边界，把完整仓库、日志、私有资料都发给外部工具。
- 没有记录，下次又从同一个坑开始。
- 为了显得专业而写很多流程，但实际不减少返工。

## 判断一个 loop 是否值得保留

一个 loop 应该至少满足其中两条：

- 能减少重复解释。
- 能减少返工。
- 能提高验证质量。
- 能降低误改、误删、误提交风险。
- 能帮助多 agent 更好协作。
- 能把经验沉淀给下一次任务。

如果一个 loop 只增加步骤，却没有减少风险、返工或上下文成本，就应该简化、自动化、替换或停用。
