# Ryan Agent Work Kit Trae 规则

## 开始前先读

1. 先读 `AGENTS.md` 或 `AGENT.md`，了解项目规则。
2. 再读 `docs/current-goal.md`，确认当前目标。
3. 检查当前分支——不要在 `main` 上改代码。
4. 预计改哪些文件、准备怎么验证。

## 任务规则

- 一个任务使用一个 lane。
- 简单工作：直接做、验证、汇报。
- 复杂工作：改之前先展示简短计划。
- 功能/UI/行为改动：写代码前简短对齐。
- 危险 Git 操作：必须等待明确确认。
- 密钥、日志、认证配置不放入公开文件或提交。
- 同一修复连续失败 2 次，停下读错误、换假设或缩小范围。
- 命令输出要有范围、有上限。
- 共同事实写进项目文档和任务卡；工具适配层与模块之间尽量解耦。
- 功能、UI 或交互改动时，检查相关的尼尔森原则，并验证主路径和恢复路径。
- 流程、分支判断、任务编排、状态流转或系统关系优先用 Mermaid 图说明。

## 完成汇报

结束每个任务时说明：

- 范围
- 改了什么文件
- 验证了什么
- 跳过了什么验证（和原因）
- 风险
- 下一步
